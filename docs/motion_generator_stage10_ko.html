BASE의 정확한 정의

이 문서의 BASE는 Stage-5 closed-loop fine-tuned tracker인 다음 checkpoint 하나를 뜻한다.

BASE=logs/WholeBodyTracking/20260711_122501-g1_29dof_wbt_gen_manager-locomotion/model_12000.pt
# checkpoint iter=12000, actor input=154, critic input=286

Stage-4 offline tracker model_09000.pt나 Stage-9 terrain checkpoint를 BASE라고 부르지 않는다. A–F의 update budget은 모두 이 BASE에서 출발한다. B는 strict architecture로 그대로 읽고, A/C/D/E/F는 각 preset의 append-only input-expansion 규칙을 사용한다.

구현 선택: 어떤 checkpoint를 공통 시작점으로 삼을지, input expansion과 optimizer 이관 방식, 이후 501 logged iteration으로 예산을 줄이는 방식은 논문 명시값이 아니다.

B에서도 balanced physical terrain은 simulator에 존재한다. 다만 generator와 tracker가 scan을 보지 않고 terrain curriculum adaptation과 heading reward, PPO update를 끈다. C와 D는 architecture가 같고 run metadata와 update 유무만 다르다. E는 generator만 scan을 소비하며 tracker actor/critic에서는 terrain_height_scan term만 제거한다. F는 D에서 heading reward weight만 0이다.

D preset은 canonical Stage-9 full preset과 training run 이름만 다르다. 따라서 아래 Stage-9 snapshot은 architecture 관점의 D 후보로 사용할 수 있지만, 저장 metadata의 run 이름은 ablation D가 아니라 canonical Stage-9 이름이다.

A fixed-reference의 비교 한계

A는 다음 약 20초 단일 WBT-schema NPZ를 기본 reference로 사용한다.

logs/motion_gen/terrain_4090/samples/manual/
lafan1_walk4_subject1_s500_rollout83x12_gen_mj.npz

이 파일은 Stage-4 fixed generated-reference 검증에 사용한 motion이다. Heading은 reference root XY velocity를 우선하고 0.5초 lookahead displacement를 차선으로 사용하며, 둘 다 정지 판정이면 root yaw로 fallback한다. A는 source clip의 원래 world heading을 유지하고 random whole-trajectory yaw augmentation을 하지 않는다.

A의 limitation: Heading 벡터만 회전하면 root/body position, orientation, velocity와 불일치하므로 그런 근사를 넣지 않았다. 올바른 yaw augmentation은 trajectory 전체 tensor를 함께 회전해야 한다. 따라서 단일 fixed clip의 heading/reference 분포를 쓰는 A와 episode마다 random heading을 조건으로 생성하는 B–F는 완전히 동일한 command 분포가 아니며, 특히 heading 지표 비교에 제한이 있다. A의 NPZ는 BASE policy와도 별개의 artifact다.

Reduced fair-budget 실행 계획

Single RTX 4090에서 먼저 비교 가능한 최소 예산으로 501 logged iterations를 사용한다. PPO loop가 BASE iteration 12,000부터 12,500까지 inclusive하게 기록하는 예산이며, 논문값이 아닌 이 재현의 축소 선택이다.

D snapshot은 3,000-iteration production run 도중 저장된 첫 500 간격 checkpoint다. Production은 계속 진행 중이지만 reduced comparison에서는 D를 이 snapshot에 고정한다. A/E/F도 같은 BASE, env 수, seed, PPO 설정과 501 logged iterations를 사용한 뒤 비교할 계획이다.

공통 terrain evaluator contract

evaluate_wbt_terrain.py는 checkpoint에 저장된 옛 config 대신 현재 A–F preset을 선택해 policy를 평가할 수 있다. 이 경로 덕분에 C는 misleading한 “0-step 학습 checkpoint”를 만들지 않고 BASE를 full input으로 확장해 바로 평가할 수 있다.

항목구현된 판정
Exact type quota총 episode 수가 active type 수로 나누어져야 하며 각 type에 정확히 같은 quota를 배정한다. 기본 100 episode와 4 type이면 25개씩이다. 같은 vectorized step에서 quota를 넘긴 extra episode는 모든 denominator에서 제외한다.
Fixed difficulty평가 동안 curriculum initial/min/max level을 같은 값으로 clamp하고 checkpoint env-state는 restore하지 않는다. Adaptive level 변화 없이 지정 row만 비교한다.
Pre-reset capturetermination/reward 계산 뒤, simulator reset 전에 WBT log hook에서 terminal root pose, termination/timeout mask와 step metric을 취득한다.
Signed successepisode-start target heading으로 투영한 최대 forward progress가 threshold 이상이고, episode 중 fall이 없으며 bad-tracking termination도 없어야 한다.
Fallterrain 기준 root height < 0.45 m 또는 upright cosine < 0.5가 한 step이라도 발생
Metricssuccess/fall/timeout/bad-tracking/survival/contact rate, episode length, signed progress, heading error, WBT tracking errors, reference/robot body-origin penetration proxy, active undesired-contact 판정
Correction exemplarreference max body-origin proxy가 threshold 이상이고 reference-minus-robot max proxy 개선이 threshold 이상인 첫 pre-reset frame을 선택해 compressed NPZ로 저장한다. Main JSON metadata에 found/path/threshold/tie-break/limitation을 남긴다.
Outputsschema-versioned JSON, numerator/denominator를 포함한 summary CSV, per-episode CSV
Provenancetracker와 generator checkpoint absolute path/SHA-256, seed, fixed level, metrics config, full effective experiment config를 저장

Success threshold 기본값은 signed progress 1.5 m다. Episode record는 timeout 또는 bad-tracking termination 때 닫히며, survival은 timeout이면서 fall/bad-tracking이 없는 경우다. Body-origin penetration은 terrain query 높이와 rigid-body origin Z의 차이일 뿐 collision-shape/mesh intersection이 아니다. Undesired contact는 active reward term의 contact-force 판정을 그대로 재사용한다.

Correction exemplar의 기본 gate는 reference max body-origin proxy ≥ 0.02 m이면서 reference_max - robot_max ≥ 0.01 m다. 처음 조건을 만족한 timestep에서 동시에 여러 env가 맞으면 가장 낮은 env id 하나를 고른다. NPZ에는 raw policy action, root state, target heading, terrain type/level, evaluation/episode step, body name, reference/robot body position, 각 body의 queried terrain height와 penetration proxy, max와 signed improvement를 넣는다. Local scan이 구성된 variant는 scan height, anchor XY/yaw, local/world XY, grid, flatten order와 unit도 함께 저장하고, 미구성 variant는 명시적 false flag와 빈 배열을 저장한다.

Exemplar의 의미 제한: 저장 조건은 rigid-body origin 높이 proxy가 reference보다 robot에서 작아진 첫 상관 사례일 뿐이다. Collision shape penetration이 해소됐다는 증거도, policy가 잘못된 reference를 의도적으로 수정했다는 인과 증거도 아니다. 조건을 만족한 frame이 없으면 NPZ를 만들지 않고 JSON에 found=false, path=null을 남긴다. 실제 evaluation이 아직 실행되지 않았으므로 현재 exemplar NPZ도 없다.

Generator는 기본적으로 fixed sampling seed를 쓰는 deterministic mode로 바꾸고 evaluation seed와 fixed terrain level을 metadata에 남긴다. 다만 torch_deterministic 기본값은 false이므로 “모든 Isaac Sim 실행이 bitwise 동일하다”는 보장은 아니다. 불완전한 episode quota는 기본적으로 오류 처리한다.

Implementation-only: accumulator, output writer, callback stop signal과 config invariant는 unit test를 통과했지만 Isaac Sim에서 A–F 중 어느 checkpoint도 이 evaluator로 아직 실행하지 않았다. 따라서 JSON/CSV 성능 산출물은 아직 없다.

Obstacle height와 unseen rough 실행 template

아래는 D snapshot을 예로 든 실행 예정 명령이다. Tyro list literal과 evaluator config parsing까지만 확인했으며 Isaac Sim 평가를 실행하지 않았다. A–F의 해당 checkpoint/preset으로 반복해야 실제 ablation 표가 된다.

PY=~/.holosoma_deps/miniconda3/envs/hssim/bin/python
EVAL=src/holosoma/holosoma/evaluate_wbt_terrain.py
DCKPT=logs/WholeBodyTracking/20260713_100222-g1_29dof_wbt_gen_terrain_manager-locomotion/model_12500.pt
GEN=logs/motion_gen/terrain_robust_fk_4090/checkpoints/final.pt
SEED=data/motion_gen/processed_paperscale/lafan1_walk4_subject1.npz
PRESET=g1_29dof_wbt_ablation_d_full_finetune

# 30 cm: box/hurdle height, stair maximum elevation을 모두 0.30 m로 고정
$PY $EVAL --checkpoint $DCKPT --experiment-preset $PRESET \
  --variant D_30cm --episode-count 100 --fixed-terrain-level 0 \
  --generator-checkpoint $GEN --motion-file $SEED --training.num-envs 4 \
  --output-prefix stage10_d_30cm \
  --terrain.terrain-term.curriculum-layout.box-height-range '[0.30,0.30]' \
  --terrain.terrain-term.curriculum-layout.stair-height-range '[0.30,0.30]' \
  --terrain.terrain-term.curriculum-layout.hurdle-height-range '[0.30,0.30]'

# 60 cm stress test: 학습 height range 밖의 동일 override
$PY $EVAL --checkpoint $DCKPT --experiment-preset $PRESET \
  --variant D_60cm --episode-count 100 --fixed-terrain-level 0 \
  --generator-checkpoint $GEN --motion-file $SEED --training.num-envs 4 \
  --output-prefix stage10_d_60cm \
  --terrain.terrain-term.curriculum-layout.box-height-range '[0.60,0.60]' \
  --terrain.terrain-term.curriculum-layout.stair-height-range '[0.60,0.60]' \
  --terrain.terrain-term.curriculum-layout.hurdle-height-range '[0.60,0.60]'

# Unseen rough: default 4-way training layout을 바꾸지 않는 opt-in single type
$PY $EVAL --checkpoint $DCKPT --experiment-preset $PRESET \
  --variant D_unseen_rough_l9 --episode-count 100 --fixed-terrain-level 9 \
  --generator-checkpoint $GEN --motion-file $SEED --training.num-envs 4 \
  --output-prefix stage10_d_unseen_rough_l9 \
  --terrain.terrain-term.curriculum-layout.terrain-types "['rough']"

rough는 curriculum layout의 허용 type으로만 opt-in 추가됐다. Production 학습 preset의 [flat, box, stair, hurdle] 목록과 25%씩의 balanced sampling은 바뀌지 않았다. 따라서 rough는 이 학습에서 보지 않은 type으로 평가할 수 있다.

구현 선택: 30/60 cm 고정 geometry, level 0/9, episode 100개, 4 env와 output naming은 평가 계획의 선택이다. 특히 60 cm는 학습 obstacle range 밖 stress test이며 “통과 가능 높이”를 뜻하지 않는다.

PyTorch CUDA latency benchmark 범위

benchmark_inference_latency.py는 GPU에 미리 올라간 tensor를 입력으로 세 workload를 각각 warm-up/측정한다: frozen 2-step generator, empirical normalization을 포함한 deterministic tracker actor, 두 module의 sequential call. CUDA event와 synchronized host clock으로 mean/median/p95/min/max/population std를 JSON에 기록하고, tracker + generator / 25의 policy-step당 amortized estimate도 별도 표기한다.

포함제외
PyTorch CUDA forward, generator canonicalization/output unpack, tracker empirical normalizer, checkpoint load·SHA-256, GPU/torch metadataIsaac Sim step, terrain raycast, observation assembly, reference buffer update, CPU↔GPU transfer, ONNX/TensorRT, 실제 functional closed loop

Tracker input은 checkpoint normalizer mean, generator condition은 지정 motion clip anchor의 history/heading/terrain 또는 zero scan을 사용한다. 따라서 sequential timing은 두 module을 같은 CUDA stream에서 연달아 잰 값이지 generator output이 tracker observation으로 연결된 end-to-end latency가 아니다.

# 실행 예정 — 아직 GPU benchmark를 수행하지 않음
$PY -m holosoma.motion_gen.scripts.benchmark_inference_latency \
  --generator-checkpoint $GEN --tracker-checkpoint $DCKPT \
  --motion-clip $SEED --device cuda:0 --batch-size 1 \
  --ddim-steps 2 --warmup 50 --measure 500 \
  --replan-interval-policy-steps 25 \
  --output logs/motion_gen/inference_latency/stage10_d_pytorch_cuda.json
Implementation-only: RTX 4090 측정 output은 아직 없다. 이 benchmark가 실행되더라도 그 결과는 PyTorch module-only latency이며 ONNX/TensorRT 또는 simulator end-to-end latency라고 보고하면 안 된다.
