BASE의 정확한 정의

이 문서의 BASE는 Stage-5 closed-loop fine-tuned tracker인 다음 checkpoint 하나를 뜻한다.

BASE=logs/WholeBodyTracking/20260711_122501-g1_29dof_wbt_gen_manager-locomotion/model_12000.pt
# checkpoint iter=12000, actor input=154, critic input=286

Stage-4 offline tracker model_09000.pt나 Stage-9 terrain checkpoint를 BASE라고 부르지 않는다. A–F의 update budget은 모두 이 BASE에서 출발한다. B는 strict architecture로 그대로 읽고, A/C/D/E/F는 각 preset의 append-only input-expansion 규칙을 사용한다.

구현 선택: 어떤 checkpoint를 공통 시작점으로 삼을지, input expansion과 optimizer 이관 방식, 이후 501 logged iteration으로 예산을 줄이는 방식은 논문 명시값이 아니다.

B에서도 balanced physical terrain은 simulator에 존재한다. 다만 generator와 tracker가 scan을 보지 않고 terrain curriculum adaptation과 heading reward, PPO update를 끈다. C와 D는 architecture가 같고 run metadata와 update 유무만 다르다. E는 generator만 scan을 소비하며 tracker actor/critic에서는 terrain_height_scan term만 제거한다. F는 D에서 heading reward weight만 0이다.

D preset은 canonical Stage-9 full preset과 training run 이름만 다르다. 수정 전 Stage-9 snapshot은 저장 metadata의 run 이름이 ablation D가 아니라 canonical Stage-9 이름이며, architecture/integrity provenance로만 사용한다. Terrain 성능용 D는 reset-aligned rerun으로 교체한다.

A fixed-reference의 비교 한계

A는 다음 약 20초 단일 WBT-schema NPZ를 기본 reference로 사용한다.

logs/motion_gen/terrain_4090/samples/manual/
lafan1_walk4_subject1_s500_rollout83x12_gen_mj.npz

이 파일은 Stage-4 fixed generated-reference 검증에 사용한 motion이다. Heading은 reference root XY velocity를 우선하고 0.5초 lookahead displacement를 차선으로 사용하며, 둘 다 정지 판정이면 root yaw로 fallback한다. A는 source clip의 원래 world heading을 유지하고 random whole-trajectory yaw augmentation을 하지 않는다.

A의 limitation: Heading 벡터만 회전하면 root/body position, orientation, velocity와 불일치하므로 그런 근사를 넣지 않았다. 올바른 yaw augmentation은 trajectory 전체 tensor를 함께 회전해야 한다. 따라서 단일 fixed clip의 heading/reference 분포를 쓰는 A와 episode마다 random heading을 조건으로 생성하는 B–F는 완전히 동일한 command 분포가 아니며, 특히 heading 지표 비교에 제한이 있다. A의 NPZ는 BASE policy와도 별개의 artifact다. 또한 XY를 reset origin으로 재정렬하고 clip-end wrap을 막은 497개의 유효 500-step start window 중 51개(10.26%)는 trajectory 자체가 4 m tile half-width를 넘는다. 이 natural tile-crossing은 reanchor 버그와 다른 A 단일 clip의 구조적 제한이다.

공통 terrain evaluator contract

evaluate_wbt_terrain.py는 checkpoint에 저장된 옛 config 대신 현재 A–F preset을 선택해 policy를 평가할 수 있다. 이 경로 덕분에 C는 misleading한 “0-step 학습 checkpoint”를 만들지 않고 BASE를 full input으로 확장해 바로 평가할 수 있다.

항목구현된 판정
Exact type quota총 episode 수가 active type 수로 나누어져야 하며 각 type에 정확히 같은 quota를 배정한다. 기본 100 episode와 4 type이면 25개씩이다. 같은 vectorized step에서 quota를 넘긴 extra episode는 모든 denominator에서 제외한다.
Fixed difficulty평가 동안 curriculum initial/min/max level을 같은 값으로 clamp하고 checkpoint env-state는 restore하지 않는다. Adaptive level 변화 없이 지정 row만 비교한다.
Phase / clip horizon매 episode 유효 phase를 uniform sampling하고, 실효 episode 길이를 fps/control decimation에서 계산해 기본 10 s에 phase_horizon_steps=500을 강제한다. HoloSoma timeout은 episode_length_buf > max_episode_length이므로 accumulator에는 timeout episode가 501 step으로 기록되지만, command는 reset 전 정확히 500회 advance하므로 horizon 500이 맞다. Fixed reference가 episode 전 clip end에 도달해 wrap/reset하지 않는다.
Reset XY alignmentA–F 모두 선택 phase의 root XY를 배정된 8 m tile 중심으로 재정렬하고, 같은 상수 translation을 모든 body/root/object reference에 적용해 relative trajectory를 보존한다.
Deterministic generator identityGenerated variant는 base seed에 env id, episode ordinal, replan ordinal을 독립적으로 합성한다. Batch 순서·subset·async reset이 바뀌어도 같은 identity의 DDIM condition noise를 보존한다.
Pre-reset capturetermination/reward 계산 뒤, simulator reset 전에 WBT log hook에서 terminal root pose, termination/timeout mask와 step metric을 취득한다.
Signed successepisode-start target heading으로 투영한 최대 forward progress가 threshold 이상이고, episode 중 fall이 없으며 bad-tracking termination도 없어야 한다.
Fallterrain 기준 root height < 0.45 m 또는 upright cosine < 0.5가 한 step이라도 발생
Metricssuccess/fall/timeout/bad-tracking/survival, episode length, signed progress, heading error, WBT tracking errors, reference/robot body-origin penetration proxy, active undesired-contact 판정
Contact 집계episode/undesired_contact_rate는 episode 동안 한 번이라도 발생했는지의 OR이다. 별도로 undesired_contact_any step 수 / 전체 rollout step과 undesired-contact body 수 / 전체 rollout step을 기록한다. 세 값은 서로 대체할 수 없다.

Success threshold 기본값은 signed progress 1.5 m다. Episode record는 timeout 또는 bad-tracking termination 때 닫히며, survival은 timeout이면서 fall/bad-tracking이 없는 경우다. Body-origin penetration은 terrain query 높이와 rigid-body origin Z의 차이일 뿐 collision-shape/mesh intersection이 아니다. Undesired contact는 active reward term의 contact-force 판정을 그대로 재사용한다.

Correction exemplar의 기본 gate는 reference max body-origin proxy ≥ 0.02 m이면서 reference_max - robot_max ≥ 0.01 m다. 처음 조건을 만족한 timestep에서 동시에 여러 env가 맞으면 가장 낮은 env id 하나를 고른다. NPZ에는 raw policy action, root state, target heading, terrain type/level, evaluation/episode step, body name, reference/robot body position, 각 body의 queried terrain height와 penetration proxy, max와 signed improvement를 넣는다. Local scan이 구성된 variant는 scan height, anchor XY/yaw, local/world XY, grid, flatten order와 unit도 함께 저장하고, 미구성 variant는 명시적 false flag와 빈 배열을 저장한다.

Exemplar의 의미 제한: 저장 조건은 rigid-body origin 높이 proxy가 reference보다 robot에서 작아진 첫 상관 사례일 뿐이다. Collision shape penetration이 해소됐다는 증거도, policy가 잘못된 reference를 의도적으로 수정했다는 인과 증거도 아니다. 조건을 만족한 frame이 없으면 NPZ를 만들지 않고 JSON에 found=false, path=null을 남긴다. Corrected-protocol 4-episode smoke에서 exemplar NPZ/PNG가 생성됐지만, legacy-misaligned-trained tracker의 단일 proxy frame이므로 최종 사례 체크를 충족하지 않는다.

Generator는 fixed base seed와 env/episode/replan identity를 쓰는 deterministic per-env mode로 바꾸고 evaluation seed와 fixed terrain level을 metadata에 남긴다. 다만 torch_deterministic 기본값은 false이므로 “모든 Isaac Sim 실행이 bitwise 동일하다”는 보장은 아니다. 불완전한 episode quota는 기본적으로 오류 처리한다.

  • F는 survival 99%지만 progress 0.082 m, heading error 1.555 rad, success 0%로 사실상 정지했다. 이 protocol의 directed motion에는 heading reward가 필수였다는 결과다.
  • A는 fixed 단일 clip, B–F는 random heading generator라 command 분포가 다르므로 A와의 절대 비교는 제한적이다.

RTX 4090 PyTorch CUDA latency

benchmark_inference_latency.py는 GPU에 미리 올라간 tensor를 입력으로 세 workload를 각각 warm-up/측정한다: frozen 2-step generator, empirical normalization을 포함한 deterministic tracker actor, 두 module의 sequential call. CUDA event와 synchronized host clock으로 mean/median/p95/min/max/population std를 JSON에 기록하고, tracker + generator / 25의 policy-step당 amortized estimate도 별도 표기한다.

포함제외
PyTorch CUDA forward, generator canonicalization/output unpack, tracker empirical normalizer, checkpoint load·SHA-256, GPU/torch metadataIsaac Sim step, terrain raycast, observation assembly, reference buffer update, CPU↔GPU transfer, ONNX/TensorRT, 실제 functional closed loop

Tracker input은 checkpoint normalizer mean, generator condition은 지정 motion clip anchor의 history/heading/terrain 또는 zero scan을 사용한다. 따라서 sequential timing은 두 module을 같은 CUDA stream에서 연달아 잰 값이지 generator output이 tracker observation으로 연결된 end-to-end latency가 아니다.

CUDA event, batch 1 / float32MeanMedianP95
2-step generator3.25656 ms3.18248 ms3.64224 ms
Tracker policy0.07823 ms0.07434 ms0.08369 ms
Sequential generator + tracker3.35356 ms3.28349 ms3.67616 ms

RTX 4090, PyTorch 2.7.0+cu128, CUDA 12.8에서 workload별 warm-up 50회 후 500회를 측정했다. 25 policy-step마다 generator를 호출하는 평균 amortized estimate는 0.2084916 ms/policy-step다.

# 실제 실행
$PY -m holosoma.motion_gen.scripts.benchmark_inference_latency \
  --generator-checkpoint $GEN --tracker-checkpoint $DCKPT \
  --motion-clip $SEED --device cuda:0 --batch-size 1 \
  --ddim-steps 2 --warmup 50 --measure 500 \
  --use-ema --deterministic-sampling --sampling-seed 0 \
  --replan-interval-policy-steps 25 \
  --output logs/terrain_evaluations/stage10/corrected_seed42_v1/latency/D_final_pytorch_cuda.json
범위 제한: 이 수치는 PyTorch module-only JSON이다. Isaac Sim step, terrain raycast, observation/reference assembly, bus/transfer, functional closed loop, ONNX/TensorRT를 포함하지 않으므로 배포 end-to-end latency라고 보고하지 않는다.

남은 문제

  • Seed 42 한 번뿐이므로 A–F 차이와 D fair→final 회복에 multi-seed 신뢰구간이 없다.
  • E가 D fair보다 좋아 tracker terrain scan의 편익이 입증되지 않았다. 동일 command identity를 더 강하게 paired-control한 재평가가 필요하다.
  • 30/60 cm hurdle success가 모두 0이고 contact가 높으며 unseen rough가 붕괴했다. “깨끗한 obstacle crossing”은 아직 달성하지 못했다.
  • Qualified exemplar는 body-origin height proxy뿐이라 causal tracker correction, collision mesh penetration, 실제 접촉 해소를 증명하지 않는다.
  • Generator+tracker ONNX/TensorRT export, simulator 포함 end-to-end latency, MuJoCo sim-to-sim, 실기 G1 검증은 다음 단계다.
