1.배경과 목표

1·2차 구현에서 terrain 조건은 zero-scan 인터페이스(Phase A)로만 존재했다. 논문은 terrain height scan을 generator의 핵심 조건으로 사용한다 — 이번 단계에서 실제 scan을 데이터에서 추출해 조건 입력과 terrain penetration loss를 실제로 학습·검증한다.

  • Scan 추출: OmniRetarget이 climb/scene마다 제공하는 box 근사 terrain 모델에서 해석적으로 height scan 생성
  • 조건 학습: heading-aligned scan을 terrain encoder에 입력 (2차와 동일한 나머지 구조)
  • Loss: 평지 전용이던 penetration loss를 scan 보간 기반으로 확장 (경사·계단 위 body 침투 페널티)
  • 검증: 모션-terrain 정합(발-표면 clearance) 자동 검사 + climb val 성능을 2차 모델과 비교

2.Terrain 데이터

OmniRetarget 데이터셋의 models/terrain/<climb|scene>_XX/multi_boxes_z_scale_{0.8..1.2}.urdf는 스캔된 terrain을 박스들의 집합으로 근사한 모델이다:

  • 각 box는 8-vertex .obj 메시 — 꼭짓점이 world 좌표에 그대로 baked (원점 identity)
  • 바닥 z=0, 윗면 평평(z=h), footprint는 yaw-회전된 사각형
  • z-scale 변형은 URDF scale 속성의 z 성분으로 적용 — 모션 z-scale 변형과 1:1 대응

따라서 지형 높이는 해석적으로 계산 가능: h(x,y) = max{박스 윗면 높이 | (x,y)가 footprint 안}, 바깥은 지면 0. 메시 레이캐스팅 불필요.

4.모션-Terrain 정합 검증 measured

add_terrain_scans.py가 scan 부착 시 자동으로 검사: 각 클립에서 발(ankle-roll body 원점, 밑창 위 약 3.5 cm) 높이 − 발 아래 지형 높이 = clearance.

150/150 클립 통과 — 발이 지형보다 5 cm 이상 아래로 내려가는 클립 0개. 예: omni_scene_06 min clearance +3.4 cm, median +5.9 cm (ankle 원점 높이와 일치). 모션 world 좌표와 terrain 모델 좌표가 정확히 정렬됨을 실측 확인.

5.실행 명령

PY=~/.holosoma_deps/miniconda3/envs/hssim/bin/python

# 1) terrain 모델 다운로드 + scan 부착 (paperscale 데이터 준비 이후)
$PY -m holosoma.motion_gen.scripts.download_terrain
$PY -m holosoma.motion_gen.scripts.add_terrain_scans

# 2) terrain-conditioned 학습
$PY -m holosoma.motion_gen.scripts.train terrain_4090

# 3) 평가 (scan_penetration_m 지표 포함)
$PY -m holosoma.motion_gen.scripts.evaluate \
    --ckpt logs/motion_gen/terrain_4090/checkpoints/final.pt --split val

# 4) climb 클립 window 샘플 (stored scan 자동 사용)
$PY -m holosoma.motion_gen.scripts.sample \
    --ckpt logs/motion_gen/terrain_4090/checkpoints/final.pt \
    --clip omni_climb_09_z1_0 --mode window --start 150

# 5) terrain 위 rollout (생성된 root를 따라 scan 재샘플링)
$PY -m holosoma.motion_gen.scripts.sample \
    --ckpt logs/motion_gen/terrain_4090/checkpoints/final.pt \
    --clip omni_climb_09_z1_0 --mode rollout --start 100 --num-cycles 20 \
    --terrain-urdf data/motion_gen/raw/omniretarget_terrain/climb_09/multi_boxes_z_scale_1.0.urdf

# 6) terrain 박스 + GT와 함께 MuJoCo 재생 (hsretargeting env)
cd src/holosoma_retargeting/holosoma_retargeting
~/.holosoma_deps/miniconda3/envs/hsretargeting/bin/python data_conversion/view_motion_mj.py \
    --motion ../../../logs/motion_gen/terrain_4090/samples/manual/omni_climb_09_z1_0_s100_rollout20x12_gen_qpos.npz \
    --gt ../../../data/motion_gen/processed_paperscale/omni_climb_09_z1_0.npz --gt-start 100 \
    --terrain-urdf ../../../data/motion_gen/raw/omniretarget_terrain/climb_09/multi_boxes_z_scale_1.0.urdf

6.결과 measured 2026-07-11

학습

  • 200k step 완주 66분 (paperscale와 동일 속도·VRAM), scan 기반 penetration loss 활성 확인
  • 과적합 없음 — 고정 val batch 기준 best MPJPE 0.0392 (@174k), final 0.0393 (2차: 0.0423)

2차(paperscale, zero-scan) vs 3차(terrain, 실제 scan) — 동일 windows·seed, DDIM 50

Val subset지표2차 (zero-scan)3차 (real scan)
terrain val (climb_09 ×5 z-scale + scene_04) body MPJPE0.0432 m0.0457 m (동급)
body-origin scan-penetration proxy0.21 mm0.06 mm (3.5× 감소)
flat val (walk4 + run1)body MPJPE0.0566 m0.0546 m (동급)

해석 (정직하게)

  • 학습 proxy 개선: sampled body/link 원점의 scan-penetration proxy가 3.5배 감소했다. Collision shape 전체의 물리적 타당성이나 feasibility를 뜻하지 않는다.
  • MPJPE는 노이즈 수준에서 동일: 0.5초 horizon에서는 과거 2 frame이 이미 지형 상태(발 높이 등)를 강하게 함의하므로, 이 평가 설정에서는 scan 조건의 추가 정보가 크지 않다. terrain 조건의 진짜 효용은 미지의 지형 배치에서 heading 명령으로 조향할 때(receding-horizon 배포)로 예상되며, 이는 tracker 통합 후 검증 가능.
  • 당시 정성 재생의 범위: climb_09 rollout이 scan을 따라 박스에 접근하는 장면을 MuJoCo에서 확인했지만, 이 viewer는 qpos를 강제 지정하고 contact를 끈 상태라 “올라섬”이나 feasibility의 증거가 아니다. 후속 collision-shape gate에서 최신 robust+FK rollout은 최대 0.260 m 침투로 실패했다.

7.남은 한계

  • chair scene의 의자 오브젝트는 scan에 없음 — scan은 고정 stage/platform 박스만 포함 (움직이는 오브젝트 조건은 별도 문제)
  • Take 10클립은 terrain 모델 미제공 → zero-scan 유지
  • scan grid는 anchor 시점 고정(0.5초 내 지형 변화는 grid 범위로 커버) — 더 긴 horizon엔 부족할 수 있음
  • penetration loss는 body 원점만 검사해 collision shape 표면 침투를 놓칠 수 있다. 후속 collision-shape gate와 함께 해석해야 한다.
