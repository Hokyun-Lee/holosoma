MuJoCo collision geometry와 4-way 진단으로 비교

stride-12 진단: FAIL · production-matched gate 대기
판정검증 범위실측 결과 생성정량 검사직접 재생 W&B한계와 다음 단계

1. 결론

완료된 stride-12 진단에서는 warm10k 이후에도 terrain feasibility 개선을 확인하지 못했다. Autonomous-history 진단인 generated_feedback + keep_current에서 old baseline 대비 joint-limit 최대 위반은 0.02153→0.00815 rad, body-head↔FK 최대 오차는 32.65→28.24 mm로 개선됐다. 그러나 242-frame rollout의 root 오차 mean/final은 0.6377/1.5917→0.7368/1.8468 m로 커졌고, MuJoCo box 최대 침투도 0.2603→0.2639 m, 5 mm 초과 frame rate도 40.91→41.74%로 개선되지 않았다.

즉 warm-start 10k가 직접 최적화한 joint/FK proxy에는 효과가 있었지만, 이 장기 생성-output feedback 진단에서 누적되는 root drift와 collision-shape 침투까지 해결하지는 못했다. Oracle heading은 root drift를 줄여도 collision을 없애지 못했고, source-history의 작은 root 오차는 매 cycle 정답 history를 넣는 teacher-forced 진단이므로 autonomous feasibility 근거가 아니다. 다만 이 표는 12 frame=0.24 s마다 재계획했고 실제 wbt_gen.py는 25 step=0.5 s마다 재계획하므로 production cadence와 다르다. 따라서 이 결과를 최종 production gate로 사용하지 않으며, stride-25 재평가 전 production scratch full 재학습과 Stage-9 scratch PPO 재개 판단을 보류한다.

  • ☑ old baseline과 warm10k checkpoint를 동일 seed/scan의 stride-12 4-way 2-step 진단으로 비교
  • ☑ quaternion, joint limit, 속도/가속도, 재계획 경계 검사
  • ☑ predicted body head ↔ MuJoCo FK 정합 검사
  • ☑ 실제 URDF box collision depth 검사
  • ☑ 동일 source segment를 같은 scene에서 비교
  • ☑ headless GIF 실제 생성, interactive MuJoCo의 start-frame/playback 경로 회귀 테스트 및 사용자 실행 명령 준비
  • ☑ old 4-way, warm10k 학습, warm10k 4-way를 W&B run + artifact로 기록
  • ☐ actuator, torque, balance, friction을 포함한 dynamic feasibility
  • ☐ 실제 wbt_gen.py cadence와 일치하는 stride-25 production gate
진행 중 결과 제외: tail pilot 및 full-scratch 관련 실행은 완료 판정 전의 중간 상태다. 이 문서의 수치와 결론에는 완료된 old 4-way, warm10k 학습, warm10k 4-way만 포함했으며, 실행 중인 job을 완료 또는 개선 성공으로 해석하지 않는다.

4-way 진단의 의미

축모드의미
Historygenerated_feedback직전 생성 frame을 다음 cycle의 2-frame history로 사용. 장기 생성 누적오차 진단.
source_history매 cycle마다 정렬된 source 2 frame으로 되돌리는 teacher forcing. 독립 window를 이어 붙이므로 boundary continuity fail은 예상된 진단값이다.
Headingkeep_currenttarget_heading=None; anchor-local +x/current facing 사용.
oracle_cycle그 cycle의 source 미래 변위로 heading을 계산. 배포 시 알 수 없는 진단용 oracle이다.
모두 구현 선택이며 논문 값이 아니다. Collision gate의 5 mm surface tolerance, 진단용 5 cm deep-penetration threshold, 0.001 rad joint-limit tolerance, quaternion norm tolerance 0.001, body-FK max-error gate 2 cm, continuity 상한(root 5 m/s·20 rad/s, joint 20 rad/s·500 rad/s², frame joint-L2 0.5 rad)은 이 재현의 CLI threshold다. Warm10k의 fk_consistency=10.0, joint_limit=10.0, lower_body_terrain_penetration=1.0을 포함한 모든 loss weight, condition-noise 크기, warm-start/10k step, clip·start·seed·cycle 수 역시 구현 및 평가 선택이다. 논문 공개 hyperparameter로 인용하면 안 된다. Strict gate는 실제 box가 있는 terrain URDF, 정확한 14-body raw head, qpos/MJCF joint mapping이 빠지거나 불일치하면 pass하지 않는다.

4. 완료된 warm10k 4-way 진단 재현

ROOT=/home/dyros24/holosoma
PY=$HOME/.holosoma_deps/miniconda3/envs/hsmujoco/bin/python
GEN=$ROOT/logs/motion_gen/terrain_feasibility_warm10k_s42/checkpoints/final.pt
TERRAIN=$ROOT/data/motion_gen/raw/omniretarget_terrain/climb_09/multi_boxes_z_scale_1.0.urdf
OUT=$ROOT/logs/motion_gen/terrain_feasibility/climb09_warm10k_rollout_modes_2step

cd "$ROOT"
WANDB_CONSOLE=off $PY -m holosoma.motion_gen.scripts.evaluate_rollout_modes \
  --checkpoint "$GEN" --clip omni_climb_09_z1_0 \
  --terrain-urdf "$TERRAIN" --start 100 --seed 123 \
  --num-steps 2 \
  --num-cycles 20 --replan-stride 12 \
  --output-dir "$OUT" --run-mujoco-feasibility \
  --wandb-mode online --wandb-entity hkleetony-dyros \
  --wandb-project HoloSomaMotionGenerator \
  --wandb-group terrain_rollout_modes \
  --wandb-name climb09-warm10k-rollout-modes-2step

이 명령은 네 variant에 동일한 seed+cycle과 terrain sampler를 사용하고, 각 variant의 raw/qpos/feasibility JSON과 최상위 comparison.json을 쓴다. Old 결과는 GEN을 terrain_robust_fk_4090/checkpoints/final.pt, OUT을 climb09_rollout_modes_2step로 지정해 같은 조건으로 얻었다. Viewer에는 variant의 motion_qpos.npz를 바로 넣으며 별도 format 변환은 필요 없다.

주의: 위 명령은 완료된 W&B run과 동일한 --replan-stride 12 진단 재현이다. 실제 tracker 연결의 25-step cadence를 재현하는 production gate 명령이 아니다.

8. 남은 한계와 다음 단계

  1. Production cadence mismatch: 완료된 4-way 표는 12-frame(0.24 s) stride다. 실제 wbt_gen.py의 0.5 s/25-step replanning과 맞춘 재평가 전에는 최종 production gate로 사용하지 않는다.
  2. 단일 clip/seed: 이 결과는 실패를 입증하기에는 충분하지만 전체 분포의 success rate는 아니다. climb/scene별 여러 history·seed를 batch gate로 확장해야 한다.
  3. Box approximation: 실제 mesh가 아니라 OmniRetarget의 box 근사와 G1 MJCF collision shape를 사용했다.
  4. Source도 collision-perfect가 아님: climbing source의 손 contact가 box 안으로 최대 약 8.1 cm 들어가므로 contact rate만으로 generated/source 우열을 말하지 않는다.
  5. Collision metric 범위: 값은 MuJoCo pairwise contact signed gap이며 일반 mesh SDF가 아니다. Ground와 이름이 붙은 terrain box만 세고 robot self-collision은 제외한다.
  6. URDF 범위: viewer/evaluator는 world 좌표가 OBJ vertex에 baked되고 origin/rpy가 0인 OmniRetarget 8-vertex box만 지원한다. 다른 URDF는 조용히 오정렬하지 않고 오류를 낸다.
  7. 동역학 미평가: kinematic gate를 개선한 뒤 actuator가 있는 IsaacLab tracker에서 fall, torque, slip, contact, obstacle success를 별도로 평가해야 한다.
  8. Warm10k의 범위: joint-limit/FK proxy는 개선됐지만 collision/root drift는 개선되지 않았다. 다음 후보는 collision-shape 또는 sole-point terrain loss, obstacle-height-balanced sampling, generated-feedback multi-step rollout loss, root/heading composition 진단이다.
학습 결정: Stage-9 tracker production은 향후 offline-tracker warm start가 아니라 처음부터 closed-loop로 재학습한다. 다만 2026-07-14에 시작했던 full-terrain closed-loop scratch30k run은 generator gate를 우선하기 위해 약 97 update에서 의도적으로 중단했으며 initialization diagnostic일 뿐이다. 현재 실행 중인 tail pilot/full-scratch 관련 job도 완료 전 중간 상태라 이 문서에서 성능 결과로 주장하지 않는다.
