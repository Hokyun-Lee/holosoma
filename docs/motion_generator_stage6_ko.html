Task 6.1 결과 (2026-07-13)

exp:g1-29dof-wbt-gen-terrain을 별도 등록했다. 기존 exp:g1-29dof-wbt-gen은 plane 설정을 그대로 유지하고, terrain preset만 현재 HoloSoma의 procedural terrain_locomotion_mix를 사용한다.

실행 명령

PY=~/.holosoma_deps/miniconda3/envs/hssim/bin/python
GEN=logs/motion_gen/terrain_4090/checkpoints/final.pt
SEED=data/motion_gen/processed_paperscale/lafan1_walk4_subject1.npz
TRACKER=logs/WholeBodyTracking/20260711_122501-g1_29dof_wbt_gen_manager-locomotion/model_12000.pt

# 기존 flat regression (64 env × 2 iter)
$PY src/holosoma/holosoma/train_agent.py exp:g1-29dof-wbt-gen logger:disabled \
  --training.num-envs 64 --algo.config.num-learning-iterations 2 \
  --algo.config.save-interval 999999 \
  --command.setup-terms.motion-command.params.motion-config.generator-checkpoint=$GEN \
  --command.setup-terms.motion-command.params.motion-config.motion-file=$SEED

# 별도 terrain + 기존 tracker resume (64 env × 추가 2 iter)
$PY src/holosoma/holosoma/train_agent.py exp:g1-29dof-wbt-gen-terrain logger:disabled \
  --training.num-envs 64 --training.checkpoint=$TRACKER \
  --algo.config.num-learning-iterations 2 --algo.config.save-interval 999999 \
  --command.setup-terms.motion-command.params.motion-config.generator-checkpoint=$GEN \
  --command.setup-terms.motion-command.params.motion-config.motion-file=$SEED
실측 통과: flat run 20260713_072831-g1_29dof_wbt_gen_manager-locomotion과 terrain run 20260713_072855-g1_29dof_wbt_gen_terrain_manager-locomotion이 각각 2 iteration을 오류 없이 완료했다. Terrain run에서 custom mesh 생성, terrain origin 동기화, generator checkpoint step 200,000, trainable generator parameter 0, tracker model_12000.pt 및 optimizer 복원, 최종 model_12001.pt 저장을 로그로 확인했다.

좌표와 현재 한계

  • Procedural terrain은 하나의 world-frame global mesh다. 각 env의 reset root와 generator seed body 위치는 같은 terrain tile world origin을 사용하도록 동기화했다.
  • terrain_locomotion_mix 선택은 Task 6.1의 실행 분리용 구현 선택이다. 현재 구성(flat/rough/low-obstacles)은 최종 box/stair/hurdle curriculum이 아니며 Task 7.3에서 교체한다.
  • Task 6.1에서는 observation shape(Actor 154, Critic 286)을 유지해 Stage-5 tracker를 strict-load했다. Generator 입력은 아직 zero scan이며 Task 6.2–6.3에서 실제 scan으로 교체한다.

Task 6.2 결과 (2026-07-13)

Dataset 전처리와 simulator가 서로 다른 grid를 갖지 않도록 terrain_4090 checkpoint의 cfg.data.scan_grid를 단일 정의로 사용한다. 현재 checkpoint의 값은 x [-0.3, 1.3], y [-0.8, 0.8], 간격 0.1 m, 17×17=289이다. 이 범위·해상도는 논문 공개값이 아니라 Stage 3에서 정한 구현 선택이다.

계약구현·검증
좌표robot root XY와 root yaw를 기준으로 local +x=전방, +y=좌측을 world XY로 회전·이동
flattenmeshgrid(indexing="ij"), index=x_idx×17+y_idx; 즉 x-major, y-fastest
값/단위기존 TerrainLocomotion.query_terrain_heights의 GPU Warp raycast hit Z, absolute world Z metre; normalization 없음
runtime bufferenv별 (N,289) scan·(N,289,2) world XY·valid mask를 cache하며 subset env update를 지원
debugcyan scan-point draw 경로와 metadata를 포함한 compressed NPZ 저장 경로 제공

검증 명령과 결과

# CPU coordinate/order/shape/debug-save regression
$PY -m pytest src/holosoma/holosoma/motion_gen/tests/test_terrain.py -q

# simulator와 같은 Trimesh → Warp GPU raycast 경로
$PY -m holosoma.motion_gen.scripts.validate_sim_height_scan \
  --out logs/motion_gen/stage6/height_scan_debug.npz
# flat_max_abs_m=0.00001526
# obstacle_max_error_m=0.00001526
# yaw_max_error_m=0.00002289

GPU 진단 장면은 한 scan 안의 서로 겹치지 않는 y lane에 30 cm box, 10→20→30 cm stair, 60 cm hurdle을 배치했다. 같은 mesh와 robot을 world에서 90° 회전·이동한 뒤에도 local scan 차이는 최대 2.289×10⁻⁵ m였다. 오차는 z=100 m에서 시작하는 float32 ray hit의 수치 오차 범위다. 저장된 height_scan_debug.npz는 terrain_height (1,289), world_xy (1,289,2), grid, flatten 순서, 단위 metadata를 포함한다.

범위 구분: 위 box/stair/hurdle mesh는 scan 좌표·raycast 검증용 deterministic diagnostic이다. Task 6.1의 학습 preset은 아직 기존 flat/rough/depression mix이며, positive obstacle 생성과 난이도 curriculum은 Task 7.3에서 별도로 구현한다. Task 6.2는 scan 취득 API와 검증을 완료했고 generator/tracker가 이 cache를 실제로 소비하는 변경은 Task 6.3이다.
