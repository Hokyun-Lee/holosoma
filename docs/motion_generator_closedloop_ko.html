1.배경: 4차와의 차이

4차에서는 generator가 미리 만들어둔 고정 모션 파일을 tracker가 추종했다(offline). 논문의 실제 방식은 다르다: fine-tuning 중 generator가 학습 루프 안에서 로봇의 현재 측정 상태(과거 2 frame)에 조건화되어 매 0.5초 reference를 새로 생성하고, tracker는 그 실시간 reference를 추종한다. 이렇게 해야 배포 시의 receding-horizon 동작과 학습 분포가 일치한다.

2.동작 구조 (매 policy step, 50 Hz)

① 상태 이력 갱신
시뮬레이터에서 로봇 실측 상태(root pose, joint 29, tracked body 14 위치)를 generator feature(78차원)로 패킹해 최근 2 frame 이력 유지
↓
② 0.5초마다 재계획 (2 Hz)
4096개 env의 이력을 한 번에 batch → 조건 노이즈 주입(σ=0.01, 논문의 robustness 학습) → frozen generator가 2-step DDIM으로 미래 25 frame 생성 → per-env reference window 교체
↓
③ Reference 소비
기존 WBT reward/observation/termination이 읽던 인터페이스(joint/body/root/ref 상태)를 window에서 그대로 공급. torso 방향은 root 방향 + 허리 3관절 체인으로 해석적 복원. 속도는 유한차분
↓
④ 에피소드 리셋
seed 모션(임의 WBT 클립)의 임의 frame + 노이즈로 로봇 초기화, 그 frame들로 이력 seed, per-env 랜덤 target heading 샘플

문서화된 근사 (구현 선택)

  • generator representation에는 per-body 방향이 없음(논문과 동일) → relative_body_orientation·global_body_ang_vel 보상을 0으로 설정
  • reference torso 방향 = root 방향 ⊗ 허리 yaw(z)·roll(x)·pitch(y) 관절 회전 체인 (G1 XML 축 확인)
  • reference 속도 = window 유한차분 (직전 실측 frame을 시드로 사용)
  • terrain scan = 평지 zero (시뮬 지면이 평지이므로 terrain_4090 checkpoint에 대해 의미상 정확)

1,000→3,000 iteration 구간에서 모든 지표가 완만히 더 개선된 뒤 평탄화 — 폐루프 적응이 사실상 수렴.

해석

  • 적응 충격 → 빠른 회복: 고정 클립 추종 정책이 "실시간 생성 reference + 랜덤 heading" 분포로 전환되자 에피소드 길이가 47로 급락했지만, 약 350 iteration(~17분) 만에 만기 생존으로 회복 — 폐루프 fine-tuning이 의도대로 동작.
  • global position 추종이 offline보다 개선(0.334→0.456): 폐루프에서는 reference가 0.5초마다 로봇의 실측 상태에 재조건화되므로 절대 위치 드리프트가 누적될 수 없음 — 논문이 폐루프 fine-tuning을 하는 이유가 실측으로 확인된 것.
  • Generator 호출 오버헤드 무시 가능: ~20.9 iter/분 (4차 offline 21 iter/분과 동일) — 4096-env batch 2-step DDIM 재계획이 학습 속도에 영향 없음. GPU 9.3 GB.
  • 정책은 이제 임의의 랜덤 heading 명령에 대해 generator가 만드는 모션을 추종 — 사실상 heading 조종 가능한 locomotion 컨트롤러의 원형.

From-scratch 30k 완주와 비교 measured 2026-07-12

exp:g1-29dof-wbt-gen을 4차 tracker 없이 처음부터 30,000 iteration 학습한 별도 run도 오류 없이 완주했다. 저장 config의 training.checkpoint: null과 PPO resume: null로 from-scratch임을 확인했으며, 4096 env에서 약 18시간 40분 동안 500 iteration 간격 checkpoint 60개와 최종 model_29999.pt (총 61개), 대응 ONNX 61개가 생성되었다.

eval_agent.py에서 다음 모션 보기 / 방향 선택

  • 폐루프 preset은 저장된 모션 목록에서 “다음 클립”을 고르지 않는다. 매 0.5초 실제 로봇 상태에서 다음 25 frame을 확률적으로 새로 생성하므로, viewer에서는 하나의 생성 과정이 계속 이어진다.
  • heading_mode="random"은 reset할 때만 새 world-frame 방향을 균등 샘플링한다. 학습 episode는 10초지만, eval_agent.py는 기본 eval override가 100,000초라 정상 추종 중에는 10초마다 자동 reset하거나 방향을 바꾸지 않는다. 넘어짐 등 termination이 발생하면 새 방향으로 reset한다.
  • 의도적으로 10초마다 새 랜덤 방향을 보려면 아래 첫 명령처럼 eval episode 길이를 10초로 override한다. 현재 바라보는 방향을 유지하려면 두 번째 명령처럼 current를 선택한다.
  • 임의의 고정 (x,y) heading 벡터 선택과 즉시 강제 reset을 위한 CLI/키보드 경로는 아직 없다. 기존 Isaac Sim W/S/Q/E 키는 GeneratedMotionCommand heading에 연결되어 있지 않다.
# 10초마다 reset → 새 random heading
$PY src/holosoma/holosoma/eval_agent.py \
    --checkpoint logs/WholeBodyTracking/20260711_122501-g1_29dof_wbt_gen_manager-locomotion/model_12000.pt \
    --simulator.config.sim.max-episode-length-s 10

# reset 시 현재 facing direction 유지
$PY src/holosoma/holosoma/eval_agent.py \
    --checkpoint logs/WholeBodyTracking/20260711_122501-g1_29dof_wbt_gen_manager-locomotion/model_12000.pt \
    --command.setup-terms.motion-command.params.motion-config.heading-mode current

6.남은 한계 / 다음 단계

현재 상태 (2026-07-14): 위 model_12000.pt와 model_29999.pt는 Stage 5 평지 폐루프 결과로 보존한다. 새 terrain closed-loop tracker의 from-scratch 학습은 generator가 strict MuJoCo 장기 self-feedback feasibility gate를 통과할 때까지 보류 중이다. 먼저 terrain-feasibility objective로 generator를 from scratch 재학습하고, 관통·관절 범위·replan 연속성을 장기 rollout에서 검증한 뒤 tracker PPO를 다시 시작한다.
  • per-body reference 방향·각속도 보상은 zero-weight (generator representation에 body 방향 없음 — 논문과 동일한 제약)
  • 조건 노이즈 σ=0.01은 구현 선택 — 논문은 노이즈 주입 사실만 명시, 크기는 비공개
  • terrain은 평지(zero scan) — 시뮬레이션에 박스 지형을 세우고 실제 scan을 물리면 terrain-aware 폐루프로 확장 가능
  • 다음 단계: 충분한 iteration까지 학습 → ONNX/TensorRT export(2-step generator + tracker) → MuJoCo sim-to-sim → 실기 G1
