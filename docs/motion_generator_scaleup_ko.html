2차: 논문 규모 데이터 확장

11클립(6.8분) → 195클립(~2.7시간)으로 확장해 diffusion motion generator를
재학습하고 일반화 성능을 재평가한 작업 기록

1.배경과 목표

1차 구현(motion_generator_ko.html)은 11클립 ≈ 6.8분으로 파이프라인을 검증했지만, 학습에 없던 val 클립에서 body MPJPE ≈ 0.166 m로 일반화가 부족했다. 원인은 명확히 데이터 규모(논문은 ~1시간 사용).

  • 목표: 논문 수준 이상(~1시간+)의 G1 retargeted 데이터로 재학습하여 val 일반화 개선을 확인
  • 비교 기준: 1차와 동일한 val 클립(walk4_subject1, climb_09)을 유지해 직접 비교 가능하게 함

Leakage 방지 val split

동일 안무·동일 씬의 변형이 train에 남지 않도록 시퀀스 그룹 전체를 hold-out:

  • lafan1_walk4_subject1 — 1차와 동일한 val 클립 (walk4는 subject1만 존재)
  • lafan1_run1_subject2, lafan1_run1_subject5 — run1 시퀀스 전체 (동일 안무의 다른 subject가 train에 남는 leakage 차단)
  • omni_climb_09_z0_8 … z1_2 — climb_09의 모든 z-scale 변형 (변형 간 근사 중복 차단)
  • omni_scene_04 — chair scene 하나

val ≈ 13분 / train ≈ 2.5시간. LAFAN1 동일 시퀀스의 다른 subject(예: walk3_subject1~5)는 같은 안무의 다른 연기라 train 내 중복도가 있음을 유의(문서화된 한계).

4.실행 명령

PY=~/.holosoma_deps/miniconda3/envs/hssim/bin/python
PYRT=~/.holosoma_deps/miniconda3/envs/hsretargeting/bin/python

# 1) 데이터 준비 (다운로드 ~90MB → FK 변환 → split)
bash demo_scripts/prepare_motion_gen_data.sh paperscale

# 2) 학습 (RTX 4090, 200k step)
$PY -m holosoma.motion_gen.scripts.train paperscale_4090

# 3) 평가 (val: walk4 + run1 + climb_09 + scene_04)
$PY -m holosoma.motion_gen.scripts.evaluate \
    --ckpt logs/motion_gen/paperscale_4090/checkpoints/<best>.pt --split val

# 4) 샘플 생성 + GT와 MuJoCo 동시 재생
$PY -m holosoma.motion_gen.scripts.sample \
    --ckpt logs/motion_gen/paperscale_4090/checkpoints/<best>.pt \
    --clip lafan1_walk4_subject1 --mode rollout --num-cycles 16
cd src/holosoma_retargeting/holosoma_retargeting
$PYRT data_conversion/view_motion_mj.py \
    --motion <..._gen_qpos.npz> \
    --gt ../../../data/motion_gen/processed_paperscale/lafan1_walk4_subject1.npz --gt-start 0
1차 데이터·체크포인트는 그대로 유지됩니다. <best>.pt는 metrics.json에서 val 지표가 가장 좋은 step의 checkpoint를 고르세요.

전 모션 테스트 가이드

어떤 클립이든 아래 절차로 확인할 수 있습니다. 변수 정의:

PY=~/.holosoma_deps/miniconda3/envs/hssim/bin/python
PYRT=~/.holosoma_deps/miniconda3/envs/hsretargeting/bin/python
CKPT=logs/motion_gen/paperscale_4090/checkpoints/final.pt
DATA=data/motion_gen/processed_paperscale
  1. 클립 목록 (195개): ls $DATA | sed 's/.npz//' — val 9개는 data/motion_gen/splits/splits_paperscale.json 참조
  2. GT 원본만 재생 (모델 무관, 데이터 확인): 
    cd src/holosoma_retargeting/holosoma_retargeting
$PYRT data_conversion/view_motion_mj.py --motion ../../../$DATA/<클립>.npz
  3. window 모드 — 0.5초 단일 예측. GT 추종 정확도를 볼 때는 이걸 사용: 
    $PY -m holosoma.motion_gen.scripts.sample --ckpt $CKPT \
    --clip <클립> --mode window --start <프레임>
# → samples/manual/<클립>_s<N>_win.png (GT 실선 vs 생성 파선 plot)
  4. rollout 모드 — 장기 생성 + GT 오버레이 재생: 
    $PY -m holosoma.motion_gen.scripts.sample --ckpt $CKPT \
    --clip <클립> --mode rollout --start <프레임> --num-cycles 25
cd src/holosoma_retargeting/holosoma_retargeting
$PYRT data_conversion/view_motion_mj.py \
    --motion ../../../logs/motion_gen/paperscale_4090/samples/manual/<클립>_s<N>_rollout25x12_gen_qpos.npz \
    --gt ../../../$DATA/<클립>.npz --gt-start <프레임>   # sample의 --start와 동일
  5. val 클립 일괄 생성 + GIF: 
    for CLIP in lafan1_walk4_subject1 lafan1_run1_subject2 lafan1_run1_subject5 omni_climb_09_z1_0 omni_scene_04; do
  $PY -m holosoma.motion_gen.scripts.sample --ckpt $CKPT --clip $CLIP --mode rollout --start 100 --num-cycles 25
  (cd src/holosoma_retargeting/holosoma_retargeting && $PYRT data_conversion/view_motion_mj.py \
     --motion ../../../logs/motion_gen/paperscale_4090/samples/manual/${CLIP}_s100_rollout25x12_gen_qpos.npz \
     --gt ../../../$DATA/$CLIP.npz --gt-start 100 --video /tmp/${CLIP}.gif)
done
  6. 정량 평가: $PY -m holosoma.motion_gen.scripts.evaluate --ckpt $CKPT --split val
해석 주의 — 길이와 GT 추종에 관해:
  • rollout 길이 = (past 2 + cycles×12) / 50 s. 기본 16 cycle = 3.9초이며 --num-cycles 50이면 12초. 클립 끝까지가 아니라 원하는 만큼 생성하는 것.
  • rollout에서 생성이 GT와 점점 달라지는 것은 정상입니다. 모델은 과거 2 frame + heading만 조건으로 "그럴듯한 미래"를 생성하는 것이지 GT를 복사하는 것이 아니며, cycle마다 자기 출력 위에서 재계획하므로 GT 궤적과 자연히 갈라집니다. GT 추종 정확도는 window 모드(0.5초)로 판단하세요.
  • LAFAN1 클립 시작부(~2초)는 T-pose 캘리브레이션 잔여 구간이라 팔을 벌리고 서 있습니다. --start 100 이상에서 시작하면 정상 동작 구간입니다.

7.남은 한계

  • LAFAN1 동일 시퀀스의 subject 간 안무 중복이 train 내부에 존재 (val은 시퀀스 그룹 단위로 차단됨)
  • terrain 조건은 여전히 zero-scan (Phase A) — climb 데이터에 실제 height scan을 붙이는 Phase B가 다음 순서
  • receding-horizon 장기 rollout의 분포 이탈은 완화됐지만 근본 해결은 폐루프 tracker fine-tuning (다음 단계)
  • 2-step 추론 품질 미검증 (검증 경로는 DDIM 50)
  • LAFAN1 학습분 포함 → 모델·결과물은 CC BY-NC-ND 비상업 조건 상속
