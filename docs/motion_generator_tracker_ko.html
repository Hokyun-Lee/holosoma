1.배경과 목표

논문 시스템의 3번째 모듈: diffusion generator가 만드는 reference 모션을 물리 로봇이 실제로 추종할 수 있어야 한다. 이 단계는 새 tracker를 만드는 것이 아니라, 생성 모션이 HoloSoma에 이미 있는 WBT RL task(PPO, Isaac Sim)에 그대로 들어가는지 검증하고 추종 정책을 학습한다.

  • generator 출력 → *_gen_qpos.npz → MuJoCo FK 변환 → WBT schema npz (1차부터 설계된 export 경로)
  • 기존 exp:g1-29dof-wbt 실험 설정을 수정 없이 사용 — motion_file만 생성 모션으로 교체
  • 이번 단계 범위: 단일 생성 모션 추종 학습. 폐루프 generator-tracker fine-tuning은 다음 단계

2.연결 구조

항목내용
Reference 모션terrain_4090 generator의 20초 receding-horizon rollout (walk4 val 클립 시작, 997 frames @50 Hz, deterministic DDIM 50)
변환convert_data_format_mj_headless.py로 전체 WBT schema(51 body + 속도) 생성 — 이 파일이 tracker의 MotionLoader가 요구하는 형식과 정확히 일치
Taskexp:g1-29dof-wbt: PPO, 4096 envs, 14개 tracked body reward — generator representation의 14개 body와 동일 목록(1차 설계에서 의도적으로 맞춤)
수정한 코드없음 (기존 task 재사용)

3.실행 명령

PY=~/.holosoma_deps/miniconda3/envs/hssim/bin/python
GEN=logs/motion_gen/terrain_4090/samples/manual

# 1) 20초 reference 생성 + WBT 변환 (완료된 파일 재사용 가능)
$PY -m holosoma.motion_gen.scripts.sample \
    --ckpt logs/motion_gen/terrain_4090/checkpoints/final.pt \
    --clip lafan1_walk4_subject1 --mode rollout --start 500 --num-cycles 83
cd src/holosoma_retargeting/holosoma_retargeting
~/.holosoma_deps/miniconda3/envs/hsretargeting/bin/python \
    data_conversion/convert_data_format_mj_headless.py \
    --input-file <...>_gen_qpos.npz --output-name <...>_gen_mj.npz --output-fps 50
cd ../../..

# 2) smoke (64 envs, 10 iterations — 파이프라인 확인)
$PY src/holosoma/holosoma/train_agent.py exp:g1-29dof-wbt logger:disabled \
    --training.num-envs 64 --algo.config.num-learning-iterations 10 \
    --command.setup_terms.motion_command.params.motion_config.motion_file=$GEN/lafan1_walk4_subject1_s500_rollout83x12_gen_mj.npz

# 3) 본 학습 (4096 envs)
$PY src/holosoma/holosoma/train_agent.py exp:g1-29dof-wbt logger:disabled \
    --command.setup_terms.motion_command.params.motion_config.motion_file=$GEN/lafan1_walk4_subject1_s500_rollout83x12_gen_mj.npz

4.결과 measured 2026-07-11

Smoke (64 envs × 10 iter)

생성 모션이 task 코드 수정 없이 로드·학습됨. checkpoint(.pt)와 ONNX가 iteration마다 자동 export — 1차에서 설계한 export 스키마가 tracker 요구 형식과 정확히 일치함을 실증.

본 학습 — 의도적으로 30%(9,000/30,000 iter)에서 중단 후 경과 확인

  • 4096 envs, PPO, 약 21 iter/분 (전체 30k ≈ 24시간 estimated — 실측 속도 외삽)
  • run: logs/WholeBodyTracking/20260711_021742-g1_29dof_wbt_manager-locomotion/, checkpoint 500 iter 간격
지표 (iteration 9,012)시작30% 시점해석
평균 에피소드 길이88 스텝500 스텝 = 10초 만기생성 모션 추종 중 넘어지지 않음
relative body position 보상0.030.985 / 1.0몸 상대 자세 추종 수렴
relative body orientation 보상0.010.908수렴 근접
body lin / ang velocity 보상0.010.870 / 0.805양호
global ref position / orientation 보상0.010.334 / 0.486 (상승 중)절대 위치·방향 드리프트는 후반 학습/튜닝 영역
핵심 결론: diffusion generator가 만든 20초 모션을 물리 시뮬레이션(Isaac Sim)에서 추종하는 RL 정책이 30% 학습만으로 전 에피소드 생존 수준에 도달 — generator→tracker 파이프라인이 끝까지 연결됨.

5.남은 한계 / 다음 단계

  • 단일 생성 모션 1개에 대한 추종 — 다중 모션/생성 분포 전체에 대한 tracker는 다음 과제
