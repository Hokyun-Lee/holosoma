1.프로젝트 목표

논문 전체 시스템

주 논문은 (1) 인간 모션을 수집·retargeting해 데이터셋을 만들고, (2) terrain과 heading을 조건으로 미래 0.5초의 전신 모션을 생성하는 diffusion motion generator를 학습하고, (3) 생성된 reference를 추종하는 RL motion tracker를 학습한 뒤, (4) 두 모듈을 폐루프로 fine-tuning하고, (5) 실제 로봇에서 0.25초마다 재계획하는 receding-horizon 방식으로 배포합니다.

이번 1차 구현 범위

  • G1 retargeted .npz 데이터 파이프라인 (11개 클립, 총 약 6.8분, 50 Hz)
  • Feature 추출·정규화, 조건부 diffusion generator 학습/샘플링
  • 단일 RTX 4090 학습 config, checkpoint 저장/재개, 정량 평가·시각화·.npz export
  • RL tracker 연결을 위한 추론 API(MotionGenerator) 및 receding-horizon 생성

아직 구현하지 않는 범위

  • RL motion tracker 학습, 폐루프 generator-tracker fine-tuning
  • 실제 terrain height scan 조건 학습 (인터페이스만 존재, Phase B — experimental)
  • ONNX/TensorRT export, MuJoCo sim-to-sim, sim-to-real

2.논문 핵심 구조

① 데이터 수집·Retargeting
자체 영상(GVHMR) + AMASS + OmniRetarget 데이터를 contact-constrained IK로 G1에 retarget, 물리 추종 replay로 필터링, terrain 변형으로 약 1시간 분량 증강 (논문 명시)
↓
② Diffusion Motion Generator
과거 2 frame + target heading + terrain height scan을 조건으로, 0.5초(25 frame)의 root pose·joint·body-link 위치를 생성 (MDM 계열, 논문 명시)
↓
③ RL Motion Tracker
생성된 reference를 추종하는 PPO 정책 (Isaac Lab). 이번 단계 미구현
↓
④ Closed-loop Fine-tuning
generator를 고정(frozen)하고 로봇의 실측 상태를 과거 frame 조건으로 사용하여 tracker를 폐루프 fine-tuning. 이번 단계 미구현
↓
⑤ Receding-horizon 배포
0.25초마다 재계획, 배포 시 denoising 2 step, Jetson Thor에서 TensorRT 추론 약 0.02 s (논문 명시). 이번 구현은 API 수준 receding-horizon만 제공

좌표계와 joint ordering

  • World up 축: +Z, 단위: 미터/라디안, quaternion: wxyz (MuJoCo 관례)
  • Joint 순서: MuJoCo G1 모델 순서 — 왼다리 6 → 오른다리 6 → 허리 3 → 왼팔 7 → 오른팔 7 (총 29)
  • 원본별 주의: LAFAN1 CSV의 quaternion은 xyzw(변환 시 wxyz로 재배열), OmniRetarget qpos는 [quat, pos, joints] 순서(변환 시 [pos, quat, joints]로 재배열) — 모두 prepare_motions.py가 처리

6.데이터 schema

처리된 모션 파일 (HoloSoma WBT 형식, data/motion_gen/processed/*.npz)

Generator 학습 윈도우 (canonical frame)

윈도우 = 과거 2 + 미래 25 frame. anchor(마지막 과거 frame) 기준으로 root xy → 원점, yaw → 0으로 정규화하고 z는 절대값을 유지합니다. per-frame feature 78차원:

구간차원내용
[0:3]3root position (canonical)
[3:7]4root quaternion wxyz (canonical, 부호 연속화)
[7:36]29joint positions (rad)
[36:78]4214개 tracked body 위치 ×3 (canonical)

조건: 과거 2 frame(동일 78차원) + target heading 2차원 단위벡터(anchor→마지막 미래 frame 변위 방향, 5cm 미만이면 (1,0)) + terrain scan 121차원(현재 zero — Phase A).

7.모델 구조

입력 — noised future window xt (25×78, 정규화 공간) + diffusion timestep t
↓
조건 임베딩
cond token = timestep 임베딩(sinusoidal→MLP) + heading MLP + terrain MLP · 과거 2 frame은 별도 token 2개로 투영 · 각 조건은 학습된 null embedding으로 마스킹 가능(cond_dropout 0.1 → classifier-free guidance 지원)
↓
Transformer Encoder
토큰열 [cond, past×2, future×25] + sinusoidal positional encoding → 8층 · 4 head · d_model 512 · ff 1024 · GELU · dropout 0.1 (MDM 기본값 차용)
↓
출력 — future 25 token → linear → x̂₀ (25×78) 기본 x0-prediction (epsilon-prediction도 config로 선택)

Diffusion 과정

  • 학습: t ~ U[0,1000), cosine β-schedule로 q_sample → 모델이 x̂₀ 예측 → 물리 단위로 denormalize 후 loss
  • 샘플링: full-step DDPM(검증 경로) 또는 DDIM n-step (validation 기본 50 step, 논문의 2 step은 experimental 옵션)

Loss (전부 --loss.* weight로 조절)

Loss정의기본 weight출처
root_pos / joint_pos / body_posMSE (m², rad²), canonical frame1.0논문의 reconstruction loss를 성분 분해(가중치는 구현 선택)
root_quat1 − ⟨q̂/‖q̂‖, q⟩² (부호 불변)1.0구현 선택 (quaternion sign ambiguity 처리)
quat_norm(‖q̂‖−1)²0.1구현 선택
velocity시간 차분 MSE(전체 feature)1.0논문 명시 항목(형태는 MDM식 구현 선택)
bone_length인접 body 간 거리 vs GT (FK-consistency 대체)0.5구현 선택 — 미분가능 FK 부재
foot_slideGT contact proxy 구간의 발 xy 변위²0.3구현 선택 (contact label 없음 → 높이+속도 proxy)
terrain_penetrationrelu(−z)², 평지 클립에만 적용0.5논문 명시 항목의 평지 버전(experimental)

contact-consistency loss는 contact label이 없어 비활성(문서화된 제외).

Loss / metric 해석

  • train/total: 꾸준히 감소해야 함. 물리 단위 기준이라 절대값이 작게 시작합니다(초기 예측≈평균 모션).
  • val/body_mpjpe_m: 핵심 지표. 14개 body 평균 위치 오차(m). 0.5초 예측 기준 수 cm 수준이면 양호.
  • val/root_quat_err_rad: root 방향 오차(rad). val/quat_norm_dev: 0.05 이하 유지 확인.
  • val/joint_limit_violation_rate: 0에 가까워야 함.
  • val/foot_slide_m_per_s: GT contact 구간의 발 미끄러짐. 감소 추세 확인.

좋은 결과 vs 실패 결과

좋은 결과

  • plot에서 생성 궤적(파선)이 GT(실선)를 부드럽게 따라감
  • 발 높이 궤적이 지면(≈0.03 m) 아래로 파고들지 않음
  • quat norm ≈ 1 유지, rollout에서 root 경로가 연속적

실패 신호

  • 생성 joint 궤적이 고주파로 떨림 → §11 참조
  • root가 GT에서 급격히 벗어나거나 rollout이 발산
  • val 지표가 train과 크게 벌어짐(overfit) 또는 정체

11.문제 해결

증상원인·해결
CUDA OOM§8의 OOM 순서대로 축소. 다른 프로세스의 GPU 점유 확인(nvidia-smi).
Isaac Lab import 실패이번 generator 단계는 Isaac Lab을 사용하지 않습니다. tracker 단계에서 발생 시 demo_scripts/demo_*_wb_tracking.sh의 isaacsim env 재설치 절차 참조.
.npz key mismatchinspect_motion_npz로 키 확인. WBT 형식(§6) 필수 키가 없으면 convert_data_format_mj_headless.py로 재변환.
Joint ordering mismatch로더는 npz의 joint_names로 이름 매칭하므로 순서가 달라도 동작. 이름 자체가 다르면(다른 로봇/모델) 오류 발생 — G1 29-DoF 모델인지 확인.
Quaternion convention mismatch내부는 전부 wxyz. 새 데이터 소스 추가 시 prepare_motions.py에서 재배열(LAFAN1 CSV=xyzw 예시 참고). 검증: quat norm≈1, 재생 시 로봇이 뒤집히지 않음.
NaN loss5회 연속이면 자동 중단. 데이터 NaN 여부(inspect --stats), LR 축소, AMP off(--no-amp) 순으로 확인. 로더가 원천 NaN은 거부함.
Root drift (rollout 발산)receding-horizon은 자기 출력에 조건화되어 분포 이탈에 민감. --replan-stride 축소, deterministic 샘플링, 학습 스텝 증가. 근본 해결은 논문의 폐루프 fine-tuning(다음 단계).
Validation loss 정체데이터 6.8분은 작음 — 과도한 max_steps는 overfit(실측: 200k step에서 val MPJPE 0.166→0.237 m로 악화). val 지표 기준 early stop, 클립 수 확대, dropout/cond_dropout 조정.
Checkpoint incompatibilitycheckpoint에 layout(차원·이름)과 format_version이 저장되어 불일치 시 명확히 오류. body/joint 구성을 바꿨다면 재학습 필요.
Terrain scan 없음정상입니다(Phase A는 zero scan). terrain 성능 주장은 하지 않으며, penetration loss는 평지 클립에만 적용됩니다.
생성 결과가 떨림denoising step 수 확대(2→50), EMA 사용 확인, --loss.velocity weight 증가, 학습 부족 여부 확인.
Overfit은 되지만 validation 실패debug(overfit 모드) 성공 ≠ 일반화. 실측 예: 200k step 모델은 train MPJPE 0.005 m(암기) vs val 0.237 m. baseline에서 val 클립 지표로 checkpoint를 고르고, 데이터 확대가 정공법. train/val 지표를 혼동하지 말 것.

12.다음 단계 (순서대로)

  1. 데이터 확대: 10개 → 수백 클립 (OmniRetarget 전체 climb/box, AMASS retarget), terrain 증강
  2. Terrain-conditioned generator (Phase B): OmniRetarget terrain mesh에서 height scan 추출, terrain encoder 학습, penetration loss 검증
  3. HoloSoma RL motion tracker 학습: 기존 exp:g1-29dof-wbt task에 생성 모션(*_gen_mj.npz) 투입
  4. Frozen generator 폐루프 fine-tuning: 로봇 실측 상태를 과거 frame으로 사용, 노이즈 주입
  5. Generator/tracker runtime 통합: MotionGenerator API를 tracker 관측 파이프라인에 연결
  6. ONNX/TensorRT export: 2-step DDIM 그래프 export (표준 연산만 사용, 미검증)
  7. MuJoCo sim-to-sim 검증
  8. Sim-to-real: Jetson 배포, 0.25 s receding-horizon 재계획
  9. 실제 G1 검증

PY=~/.holosoma_deps/miniconda3/envs/hssim/bin/python

# 1. 환경 확인
$PY -c "import torch, holosoma; print(torch.cuda.is_available())"

# 2. 테스트 (GPU 불필요, 36개 통과 확인)
$PY -m pytest src/holosoma/holosoma/motion_gen/tests/ -q

bash demo_scripts/prepare_motion_gen_data.sh

$PY -m holosoma.motion_gen.scripts.inspect_motion_npz \
    --path data/motion_gen/processed/lafan1_walk1_subject1.npz --stats

# 5. smoke → debug → baseline
$PY -m holosoma.motion_gen.scripts.train smoke
$PY -m holosoma.motion_gen.scripts.train debug
$PY -m holosoma.motion_gen.scripts.train baseline_4090

# 6. 평가 + 샘플 생성
$PY -m holosoma.motion_gen.scripts.evaluate \
    --ckpt logs/motion_gen/baseline_4090/checkpoints/latest.pt --split val
$PY -m holosoma.motion_gen.scripts.sample \
    --ckpt logs/motion_gen/baseline_4090/checkpoints/latest.pt \
    --clip lafan1_walk4_subject1 --mode rollout --num-cycles 16
